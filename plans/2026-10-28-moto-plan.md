# Moto — milestone 1 plan

Approved 2026-10-28. Source spec: "Moto — Prototype Build Spec" (Oct 28, 2026).

Moto is a browser motocross game in the spirit of Motocross Madness 1 and 2.
Milestone 1 is a free-ride sandbox, and the only thing that matters in it is
that the bike feels heavy and punchy and is fun to jump. Every feel value lives
in `src/config.ts`.

## Stack

- **TypeScript + Vite** (same setup as Idle-Survivor)
- **Three.js** for rendering
- **Rapier** (`@dimforge/rapier3d-compat`) for physics. The compat build embeds
  its WASM, so it needs no special server headers and runs on GitHub Pages.
- **Tweakpane** for the tuning panel. It can draw live graphs, which helps when
  watching the suspension.
- **Vitest** for headless checks

We picked this over Babylon.js + Havok for three reasons. The bike's handling is
custom code with either engine, so Babylon's extras don't help with the part
that matters. Stepping Rapier ourselves makes the fixed timestep exact. And it
matches Idle-Survivor.

## How the bike works

This is an arcade model. It does not simulate real two-wheel balance.

- **Body:** one rigid body for bike and rider.
- **Wheels:** two raycast wheels. Each wheel casts a ray down, and the
  suspension is a spring and damper along it. The visible wheels sit at the ray
  hit point.
- **Tyre forces:** each tyre pushes forward (engine), backward (brake) and
  sideways (grip). Going past the grip limit makes the bike slide.
- **Steering:** the maximum steering angle is a curve over speed with tunable
  constants. Turns are tight at low speed and wide at high speed.
- **Upright helper:** a soft spring keeps the bike from falling over and leans
  it into turns from speed × turn rate. The bike can't fall over at walking pace.
- **Rider lean:** on the ground it shifts weight between the wheels (wheelies,
  nose-dives). In the air it is a pitch torque.
- **No glue:** nothing pulls the bike down except gravity and the springs, so it
  carries speed over crests.
- **Units:** real units, metres / kg / seconds (bike about 100 kg, rider about 75 kg).

## Project structure

```
src/config.ts      every feel value, bike stats, key bindings (the one tuning file)
src/main.ts        boots everything
src/core/          fixed-step loop, input layer (actions + ramps)
src/physics/       Rapier world, bike, crash detection
src/terrain/       map generator -> heightfield + ramps
src/render/        scene, bike/rider visuals, chase + free-fly cameras
src/ui/            tuning panel (generated from config), debug readout
src/maps/          map data (hill and ramp parameters)
tests/             headless checks
plans/             this plan and later step plans
docs/              the built site GitHub Pages serves (wiped on every build)
```

Physics never imports from render. The visuals read the physics state each
frame, so swapping in a real bike model means swapping one render file.

## Build order

Stop after each step so the user can ride it.

1. **Scaffold and deploy.** An empty scene with a ground plane, the fixed-step
   loop, and the live link.
2. **Terrain and plumbing.** The hilly map and a free-fly camera, plus the config
   file, the input layer and the generated tuning panel (so the hills can be
   shaped with sliders).
3. **Bike stands.** Physics body and suspension. It sits on the terrain and rolls
   downhill. This step adds the debug readout and the R reset key.
4. **Bike drives.** Throttle, brake, steering and the chase camera.
5. **Weight and air.** Rider lean, jumps and landings, plus a simple box rider
   with a head that visibly leans.
6. **Crashes.** Bad-landing and head-touch detection, the crash itself and the
   auto reset.
7. **Rider visuals.** A placeholder rider that reacts, for example knees bending
   on landings.

After step 7 we loop on tuning until milestone 1 is done.

After every step: run the tests, commit, tag `step-N`, build into `docs/`, push,
and check the live link.

## Decisions (defaults the user approved)

1. **Copy values.** The tuning panel's copy button copies only the values that
   were changed. The user pastes them to Claude, who folds them into
   `config.ts` and keeps the plain-English comments.
2. **Bad landings** fall into three bands, with the angles in config:
   - clean: smooth landing
   - sloppy: speed loss and a hard bottom-out
   - way off, or the head touches the ground: crash
3. **Steering in the air.** A small yaw you can tune. Set it to 0 to turn it off.
4. **Ramps.** Hill lips come from the heightfield and are smooth. Ramps are
   separate solid shapes with sharp lips.
5. **Hosting.** The repo is public (`Benko-E/Moto`) and served at
   https://benko-e.github.io/Moto/. The site is built locally and committed to
   `docs/`, like Idle-Survivor, so licensed raw art never has to sit in the repo.
6. **Map.** About 1 km × 1 km, with fog hiding the edge.
7. **Physics** runs at a fixed 120 Hz. Rendering interpolates between steps, so
   60 Hz and 144 Hz screens feel the same.

## Later, not now

Tricks with scoring, ragdoll crashes, race modes, AI riders, real models, and
engine sound. Choices made now must not block these.
