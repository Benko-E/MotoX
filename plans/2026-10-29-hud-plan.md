# MotoX: HUD plan

The first piece of milestone 2. Tricks need somewhere to show up, and so will
races, AI riders and a minimap later, so the HUD comes first. It's built as a
system that's easy to add to, but only fills the slots we can use today.

## What the user asked for

- A speed indicator, airtime, a place where trick names will pop up, points,
  and later totals (yours, the AI riders', points to get) and a minimap.
- Moving an element is changing one setting ("the speedometer could be top
  right, or bottom left"), and it looks right at any screen size.
- A fun hobby project, not AAA: keep it simple.

## How it works

- **A layer of web page elements over the 3D view.** Each HUD element is a
  small box of ordinary web text and graphics laid on top of the game, so
  text is sharp at any resolution and the browser does the layout. (Drawing
  the HUD into the 3D picture, or bringing in a web interface toolkit, were
  both more than a hobby game needs.)
- **Anchors.** Each element sits at one of 9 spots on the screen: topLeft,
  top, topRight, left, center, right, bottomLeft, bottom, bottomRight, plus
  a nudge in from there (x and y).
- **Any screen size.** Sizes and nudges are measured in shares of the
  window's height, so the HUD looks the same on a laptop, at 1080p or 1440p;
  a wider screen just has more room in the middle. One `hud.size` slider
  makes everything bigger or smaller.
- **Settings.** A new `hud` section in config.ts, one entry per element:

  ```ts
  hud: {
    size: 1,
    speed:    { show: true,  anchor: 'bottomRight', x: 3, y: 3 },
    airtime:  { show: true,  anchor: 'top',         x: 0, y: 4 },
    messages: { show: true,  anchor: 'center',      x: 0, y: -18 },
    points:   { show: false, anchor: 'topLeft',     x: 3, y: 3 },
  }
  ```

  In the tuning panel, `anchor` is a dropdown of the 9 spots and x, y are
  sliders, so a layout can be tried live and copied back like the other
  values. (The panel only knows numbers and on/off today; it learns
  dropdowns for anchors.)
- **Pieces.** Each element is one small self-contained piece that's handed
  the latest numbers every frame (speed, airtime, the last landing, a crash,
  and later points). Adding one later, the minimap say, is one more piece
  plus one line in the layout. A piece can also draw its own picture, which
  the minimap will need.
- **Style.** Chunky, bold, slanted numbers with a dark outline, a nod to
  Motocross Madness. No downloaded fonts: built-in ones, so it works offline
  and loads instantly.

## The first elements

- **Speedometer** (bottom right): a big km/h number, and a bar under it
  filling toward top speed.
- **Airtime** (top, middle): appears when you leave the ground, counts up
  ("AIR 1.84 s"), stays a moment after landing, then fades.
- **Messages** (centre, upper third): one place for short pop-up text. It
  takes over the amber "SLOPPY LANDING" note and the red crash banner, and
  later shows trick names ("360 + BACKFLIP"). A new message replaces the
  old; a crash shows until you're back up.
- **Points** (top left): built and placed, but hidden until tricks give it
  something to count. Totals, AI riders' points and points to get come the
  same way later.
- Not part of the HUD: the controls card at the start and the number
  readout (`), which are tools rather than HUD.

## Build steps

Stop after each so the user can look at it; test, commit, build, push.

1. **The system:** the HUD layer, anchors and screen-size scaling, the
   `hud` settings with anchor dropdowns in the panel, and the speedometer as
   the first element (to prove moving it around works).
2. **Airtime and messages:** the airtime counter, and the message area
   taking over the landing note and the crash banner.
3. **Points slot:** the hidden points element, ready for tricks; then check
   the whole HUD at a few screen sizes (1280x720, 1920x1080, ultrawide).

## Testing

The parts that decide things are plain code with tests: where an anchor
puts an element at a given screen size, when airtime shows and fades, which
message shows and for how long, how full the speed bar is. The bits that
touch the page are kept thin, and checked in the game in the browser.
